Sistema de gestión para tueste, procesado y venta de café

Cubre inventario multietapa, compras, producción (beneficiado, trillado, tueste, molido), servicios a terceros, clientes, pedidos y ventas — desde el grano cereza hasta la taza empacada con marca propia.

01

Contexto y objetivo

El negocio combina tres actividades sobre un mismo insumo — el café — con reglas de inventario distintas cada una:

Producción propia. Compra de cereza/pergamino/verde a proveedores, procesado interno y venta bajo marca propia al menudeo y mayoreo.
Servicio a terceros. Tostado, pelado, molido o procesado de café que pertenece al cliente — se cobra por el servicio, no se compra ni se vende el grano.

El sistema debe distinguir siempre estas dos rutas: un lote propio afecta inventario y costos; una orden de servicio afecta solo cuentas por cobrar.

07

Diseño de base de datos

7.1 — Tabla de auditoría (append-only, con retención)

Registra cada INSERT/UPDATE/DELETE sobre tablas críticas vía trigger SECURITY DEFINER. La inmutabilidad frente a la aplicación se logra por privilegios (sin GRANT de update/delete a los roles de API), no por un trigger bloqueador — eso deja espacio para que un job de mantenimiento sí pueda purgar registros vencidos.

create table audit_log (
  id bigint generated always as identity primary key,
  table_name text not null,
  record_id text not null,
  operation text not null check (operation in ('INSERT','UPDATE','DELETE')),
  old_data jsonb,
  new_data jsonb,
  changed_by uuid default auth.uid(),
  changed_at timestamptz not null default now()
);

-- Inmutable de cara a la app: ningún rol de API puede editar/borrar
revoke update, delete on audit_log from anon, authenticated;

-- Retención configurable — purga automática vía pg_cron (incluido en plan Free)
create or replace function fn_purge_audit_log(retencion_dias int default 15)
returns void language sql security definer as $$
  delete from audit_log
  where changed_at < now() - (retencion_dias || ' days')::interval;
$$;

select cron.schedule('purge-audit-log', '0 3 * * *', $$select fn_purge_audit_log(15)$$);

15 días es el punto de partida — súbelo si te interesa poder investigar un ajuste de inventario raro varias semanas después; a esta escala de datos, 90 días no representa un costo de almacenamiento relevante.

7.2 — Inventario de producto terminado

LOTES cubre el inventario en proceso (verde, tostado a granel, medido en kg). El producto empacado listo para vender se mide en unidades (bolsas de 250g/500g/1kg) y necesita su propio registro — como ledger, igual que ORDENES_PROCESO, para que el stock nunca se desincronice de su historial.

No todo producto viene de tu propio proceso: también puedes comprar café ya listo para reventa. Por eso productos_terminados no depende obligatoriamente de un lote propio, y el ledger admite una entrada por compra directa además del ajuste manual.

alter table productos_terminados
  alter column variedad_id drop not null,        -- opcional: reventa puede no tener variedad definida
  alter column perfil_tueste_id drop not null,   -- opcional: reventa no pasó por tu tueste
  add column origen text not null default 'produccion_propia'
    check (origen in ('produccion_propia','reventa')),
  add column proveedor_id uuid references proveedores(id);  -- de quién lo compraste, si es reventa

create table movimientos_inventario (
  id bigint generated always as identity primary key,
  producto_terminado_id uuid not null references productos_terminados(id),
  lote_origen_id uuid references lotes(id),        -- trazabilidad: de qué lote salió (null si es reventa)
  tipo_movimiento text not null
    check (tipo_movimiento in ('entrada_empacado','entrada_compra','salida_venta','ajuste')),
  cantidad int not null,                            -- positivo en entrada, negativo en salida
  referencia_id uuid,                               -- id de la venta, compra u orden de proceso que originó el movimiento
  usuario_id uuid references auth.users(id),
  creado_en timestamptz not null default now()
);

-- Stock actual: se calcula, nunca se guarda como contador editable
create view inventario_producto_terminado as
select producto_terminado_id, sum(cantidad) as stock_actual
from movimientos_inventario
group by producto_terminado_id;
tipo_movimientoCuándo se usa
entrada_empacadoSale de tu propia producción (M4 → empacado)
entrada_compraCompraste café ya listo para vender, sin pasar por tu proceso
salida_ventaSe vendió al cliente
ajusteCorrección manual: conteo físico, merma por daño, alta inicial de producto nuevo

Observabilidad

Arranca en free en ambas herramientas — suficiente para el volumen actual (5 req/s):

Sentry (Developer, $0)
5K errores/mes, captura de excepciones y trazas básicas del frontend y API routes.
Better Stack (Free, $0)
10 monitores de uptime, alertas por Slack/email si el sitio cae.

Se sube a plan pagado (~$26–34/mes cada uno) solo ante señal real: más de 5K errores/mes sostenidos, o necesidad de alertas por SMS/llamada fuera de horario.

Glosario cafetero

Cereza
Fruto del café recién cosechado, con pulpa y cáscara.
Beneficiado
Proceso que retira la pulpa de la cereza — lavado, honey o natural, según cuánto mucílago se deja.
Pergamino
Grano tras el beneficiado, aún envuelto en su cáscara interna (endocarpio).
Trillado / pelado
Retira el pergamino y deja el grano verde (oro), listo para tostar.
Verde / oro
Grano crudo sin tostar — la unidad de inventario que se compra/vende entre productores.
Tueste
Aplicación de calor según un perfil (curva de tiempo/temperatura) que define sabor y color final.
Merma
Pérdida de peso entre una etapa y la siguiente (ej. el tueste reduce el peso ~15–20%).
Documento vivo — se actualiza conforme avanza cada módulo. Próxima revisión al cierre de M2.
